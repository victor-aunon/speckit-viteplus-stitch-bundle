# FEATURE: Accessible Vanilla Dialog & Notification System

## 1. Context & Purpose
A modern, lightweight, accessible web component system built without frontend framework dependencies (Zero-Framework Vanilla JS/TS). Implements a native modal dialog using the HTML5 <dialog> API and a floating toast notification system with hardware-accelerated transitions and strict Ghost Classes compliance.

## 2. Domain Entities & Models
- DialogOptions: title (string), message (string), confirmText (string), cancelText (string), variant ('info' | 'warning' | 'danger').
- ToastNotification: id (string), message (string), durationMs (number), type ('success' | 'error' | 'info').
- DialogState: isOpen (boolean), activeElementBeforeOpen (HTMLElement).

## 3. UI Elements & CSS Stylesheets
- ModalDialog: ES Module (ModalDialog.ts) managing showModal(), close(), and accessible focus trapping.
- ToastContainer: Floating container in the top-right viewport with vertical stacking and automatic dismissal timers.
- CSS Stylesheets (src/styles/dialog.css): Semantic styling rules (.modal-backdrop, .modal-card, .modal-header, .modal-actions, .toast-item, .toast--success).
- Design Tokens: Native CSS custom properties under :root (--dialog-bg, --dialog-radius, --dialog-shadow, --transition-smooth).

## 4. Key Acceptance Criteria (Gherkin Scenarios)
- Scenario 1 (Dialog opening & focus trap):
  Given the user activates a modal trigger button
  When the showModal() method is called
  Then the dialog renders in the browser top layer, keyboard focus moves to the first interactive element, and document body scroll is locked.

- Scenario 2 (Dismissal via Escape key or backdrop):
  Given the modal dialog is currently open
  When the user presses the 'Escape' key or clicks the exterior backdrop
  Then the dialog closes with a fade-out transition and keyboard focus returns directly to the triggering element.

- Scenario 3 (Strict Ghost Classes verification):
  Given the elements dynamically created in the DOM by the component
  When check-ghost-classes.sh audits the CSS class selectors
  Then 100% of referenced classes (e.g. .modal-card, .toast-item) exist in src/styles/dialog.css with zero missing declarations.

## 5. Technical Constraints & Quality Gates
- Zero frontend frameworks: No React, Vue, Svelte, or external runtime dependencies.
- Complete Ghost Classes compliance: No unmapped dynamic class names.
- Native WCAG 2.1 AA accessibility: Support for aria-labelledby, aria-modal="true", and @media (prefers-reduced-motion: reduce).
- Centralized environment access strictly via src/config/env.ts.
- Unit tests covering the dialog lifecycle using Vitest and JSDOM.
